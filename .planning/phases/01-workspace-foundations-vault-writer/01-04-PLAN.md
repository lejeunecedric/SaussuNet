<threat_model>
ASVS L1 surface for this plan:
- **Symlinked vault content (T-04-01):** reindex walks the vault FS — canonicalize each discovered `.md` path and skip any that escapes the canonical vault root (a symlink planted inside the vault must not pull external files into the registry); skip dot-files and `_archive/`-style hidden dirs consistently with the writer's dot-prefix temp convention.
- **Registry poisoning via malformed files (T-04-02):** a page with invalid frontmatter must not abort the whole reindex — count it as a lint-style warning (stderr line `skipped <path>: <reason>`), continue, and exclude from the count. Loud but non-fatal (PATTERNS §2.8 posture, adapted: one bad file ≠ dead command).
- **Vault-id isolation (T-04-03):** every store call in reindex and the new store APIs is keyed by vault_id; reindex must clear/repopulate ONLY the configured vault's rows (a second vault's registry must survive a reindex of the first — test asserts).
- **No new transports (T-04-04):** still zero listeners; INFR-02 SC5 assertion in the acceptance test includes "no port bound by the binary" (process exits; nothing listens).
- **SQL (T-04-05):** new store APIs parameterized binds only; `clear_pages` scoped `WHERE vault_id = ?` — never an unscoped DELETE.
</threat_model>
