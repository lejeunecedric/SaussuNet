<threat_model>
ASVS L1 surface for this plan:
- **Path traversal (T-02-01):** `write-page --path` is attacker/operator-supplied. Guard order: reject absolute paths and any `..` segment on the raw input → join to vault root → canonicalize the existing parent → assert canonical result `starts_with(canonical vault_root)` → reject if the target exists and is a symlink (symlink could point outside). Reject writes into `raw/` (immutability, Pitfall 4: only raw/ is evidence, and it is written by ingestion later, never by page writes). MoriNet WebDAV lesson: canonicalize/decode BEFORE the check, never after.
- **Torn writes / crash safety (T-02-02):** temp file in the SAME directory as the target (cross-device rename is not atomic), dot-prefixed name so Obsidian/glob scans ignore leftovers, temp deleted on any failure path, rename is the last step (PATTERNS §2.5 — no MoriNet analog, establish fresh).
- **Concurrent writers (T-02-03):** one `tokio::sync::Mutex` write lock per Vault instance serializes ALL mutations (page, index, log) — Pitfall 6: log.md append-only is NOT safe under concurrent writers without the lock.
- **Malformed input (T-02-04):** unterminated/invalid frontmatter must never truncate the page (MoriNet frontmatter.rs:57-63 defensive contract); invalid frontmatter rejects the WRITE, leaving the existing file untouched.
- **Log injection (T-02-05):** titles/paths written into log.md/index.md lines are sanitized of newlines and `## [` sequences so a crafted page title cannot forge log entries.
- **Secrets (T-02-06):** nothing new; vault dir remains credential-free (T-01-01 check from Plan 01 still guards boot).
</threat_model>
