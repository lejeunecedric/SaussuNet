<objective>
Walking Skeleton, part 1+2: scaffold the two-member Cargo workspace and drive the thinnest end-to-end path — binary start → config.toml load → SQLite WAL open + full migrations → vault FS init (SCHEMA/index/log/raw) → `vault ready` — so that ROADMAP SC1 ("running the binary creates a vault") and SC5 (WAL, no external services, localhost default) are TRUE at the end of this plan.

Purpose: Everything later (writer, gen_hash, Phase 2 queue) mounts on this skeleton. It also forces the two open architecture decisions now: sqlx version pin and pre-UI operability.
Output: Building workspace, migrations (full schema, D-02), store layer with WAL options, vault init module, clap binary with `version`/`init`/`init-vault` + bare-run boot, config template, quality gate script.

Planner decisions recorded (Claude's Discretion from 01-CONTEXT.md):
- **sqlx pinned at 0.8** (not STACK's 0.9): MoriNet's Cargo.lock pins 0.8.6; two sqlx majors cannot coexist in one binary; QUAL-05 MoriNet lib integration is the binding future constraint and MoriNet's own 0.9 migration is not on our schedule. A later 0.8→0.9 bump is a mechanical migration we control. Justification lives in SKELETON.md; the pin lives in `[workspace.dependencies]`.
- **Pre-UI operability = clap CLI subcommands** (no HTTP in Phase 1): SC1 only requires "running the binary creates a vault"; the CLI is the simplest testable driver and every subcommand is assertable in integration tests. Full surface (`write-page`, `conflicts`, `reindex`) lands in later plans of this phase.
</objective>

<threat_model>
ASVS L1 surface for this plan:
- **Config/DB placement (T-01-01):** The SQLite DB and config.toml must never live inside the vault directory — a vault is served/previewed later (mdbook, MCP) and everything inside it leaks. Startup check: after resolving RuntimeConfig, if `db_path` or the config file path canonicalizes to inside `vault_root`, fail with an actionable error before opening anything.
- **Localhost default (T-01-02):** `[server].bind` default is exactly `127.0.0.1:8080`. Phase 1 opens NO listener; a test asserts the resolved default so Phase 5 cannot accidentally inherit a 0.0.0.0 default.
- **SQL injection (T-01-03):** All store APIs use parameterized `.bind()` only; no string-formatted SQL anywhere (MoriNet store idiom).
- **Secrets (T-01-04):** No credentials exist yet; `.gitignore` must cover `/data/` and `config.local.toml` so future real config never lands in git or the vault.
- **Migration integrity (T-01-05):** Migrations are `CREATE TABLE IF NOT EXISTS` + idempotent; a failed migration must abort boot loudly (no partial-schema silent operation).
</threat_model>
