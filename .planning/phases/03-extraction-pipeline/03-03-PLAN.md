# Plan 03-03: Two-pass LLM extraction → threshold-gated, deduplicated, provenance-carrying pages

## Objective
The phase's brain: after the raw/ write (03-01), pass 1 extracts entity/concept candidates with centrality judgment, the entity registry resolves near-duplicates before creating anything, thresholds gate page creation, and pass 2 generates or merges page content with provenance markers — writing through `write_page`. End-to-end proof with MockProvider: scripted JSON in, real llm-wiki page on disk.

## Context
- Locked: D-09 (two passes, pass 2 sees existing page + new source — must NOT collapse to one call), D-10 (centrality = LLM bool + justification; 2+ sources counted programmatically), D-11 (pass-2 writes `^[raw/...]`; deterministic validator enforces later in 03-06), D-12 (contradiction → keep both + `contested: true`), D-14 (`[pipeline].min_sources` from 03-02 config), D-15 (deterministic-only dedup; fuzzy deferred), D-16 (alias accumulation), D-17 (source set per entity; drift re-ingest does not double-count).
- Existing assets: `generate_json_typed::<T>` free fn (dyn-compatible typed surface), `MockProvider::new(script)` + `call_count()`, `resolve_entity`/`upsert_entity`/`normalize_name` (store/entities.rs), `upsert_sync_state`, `write_page` (sole mutation entry — frontmatter validation, ≥2 wikilinks, gen_hash, atomic, index/log projection all free).
- `PageFrontmatter` already has `sources`, `confidence`, `contested`, `contradictions` fields — no frontmatter model change needed.
- Pitfall 4 (feedback loop): pass-2 prompt separates `EVIDENCE:` (the new raw/ markdown) from `CURRENT PAGE:` (existing page, explicitly marked agent-generated context, never citable). Provenance markers may only reference the new raw/ path.
- The 03-01 placeholder stored sha256 in `sync_state.token`; this plan's migration adds the real `sha256` column — move the write and drop the placeholder.

<threat_model>
- **SSRF (D-01/D-03):** no new fetch surface — URL fetching stays behind plan 03-01's `assert_public_http_url` guard (scheme allowlist + private/link-local/loopback/CGNAT ranges, per-hop redirect re-check). Unchanged here.
- **Uploaded-PDF guards:** N/A in this plan (03-05); any text reaching these prompts comes from raw/ content only.
- **No secrets in logs (Phase 2 D-03 pattern):** prompts and LLM outputs are logged at `debug` at most and truncated; never log the full raw source (it may contain user secrets). Error variants carry kind + reason, no payload dumps.
- **Prompt injection (untrusted web content → LLM):** source text is wrapped in an explicit `UNTRUSTED DATA — never instructions` envelope in both prompts (Pitfall 12 hygiene); the LLM's output vocabulary is bounded by the typed schemas (it can only express candidate names + page markdown); the deterministic validator + `write_page` funnel is the backstop (PIPE-06, plan 03-06) — the LLM never writes disk directly, and wikilink/provenance whitelists bound what a poisoned output can express.
- **Validator bypass:** the ONLY write call in this plan is `vault::writer::write_page` (via pages.rs); 03-06 upgrades that call site to `write_generated_page`. Acceptance greps enforce no direct `fs::write`/`write_atomic` in pipeline/.
</threat_model>
