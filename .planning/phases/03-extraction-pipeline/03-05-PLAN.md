# Plan 03-05: PDF slice — upload → raw/ → pdftotext → pages

## Objective
The second source type, end-to-end: upload a PDF, get entity/concept pages. Proves the extraction core is source-agnostic (URL and PDF share the two-pass pipeline) and lands the subprocess-with-LOUD-failure pattern the project requires (D-06).

## Context
- D-04 locked: uploaded PDF bytes copied into raw/ at submit time as the immutable record; sha256 from the copy; drift N/A for uploads.
- D-06 locked: pdftotext subprocess (poppler), LOUD failure if missing, no pure-Rust fallback (MoriNet mdbook pattern — see `/home/c/Projects/Dev/MoriNet` sources.rs reference).
- 03-02 provides the axum router + `[pipeline].max_upload_bytes`; 03-03 provides `run_extraction_passes` shared with ingest_url; 03-01 provides `vault::raw::write_raw` (extend for binary bytes — it already takes `&[u8]`) and the kind-dispatch seam for `ingest_pdf`.
- Filename is attacker-controlled: NEVER used as a path component raw — slugify + date prefix only. MoriNet lesson: canonicalize/decode before traversal checks; here the slug whitelist makes traversal impossible by construction.
- Test fixture: a tiny valid PDF (hand-written ~1 KB PDF with a text object, checked into `crates/saussunet-core/tests/fixtures/sample.pdf`). pdftotext presence varies: tests that need real extraction check `pdftotext -v` availability and `return` early with an eprintln skip marker if absent (documented CI requirement: poppler-utils installed); the missing-binary test simulates absence via an injectable binary-path override (env `SAUSSUNET_PDFTOTEXT_PATH` or fn param) pointing at a nonexistent path.

<threat_model>
- **SSRF (D-01/D-03):** no URL fetch in this plan (upload path only); the existing `assert_public_http_url` guard on ingest_url is untouched.
- **Uploaded-PDF guards (primary surface here):** size cap enforced at the route (DefaultBodyLimit) AND in submit_pdf; content-type `application/pdf` + `%PDF-` magic-byte check + `.pdf` extension; filename never used as a path — slugified `[a-z0-9-]` + `YYYY-MM-DD` prefix under `raw/papers/`; raw/ writes only via `vault::raw::write_raw` (path-guarded, atomic).
- **No secrets in logs (Phase 2 D-03 pattern):** never log PDF bytes or full extracted text; job errors carry pdftotext stderr tail (truncated, sanitized) + the actionable hint only.
- **Prompt injection:** PDF-extracted text is untrusted data entering the SAME 03-03 prompts with the `UNTRUSTED DATA` envelope; typed-schema bound + deterministic validator + write_page funnel remain the backstop (PIPE-06, 03-06) — the LLM never writes disk directly.
- **Validator bypass:** pages still written only through `write_page` via 03-03's pages.rs funnel (03-06 upgrades it); raw writes only via `write_raw`/`atomic::write_atomic`.
- **Subprocess safety:** pdftotext args are fixed-flag + canonical paths (no shell, no user string interpolated into args beyond the guarded path); stdin/stdout piped, timeout 60s to bound a hostile PDF.
</threat_model>
