# Plan 03-07: Thresholds & dedup enforcement — normalization upgrade + corpus proofs (PIPE-03/04)

## Objective
Make ROADMAP SC3 fully TRUE with end-to-end corpus tests: thresholds gate exactly as specified, passing mentions never create pages, and the entity registry prevents near-duplicates deterministically. Includes the D-15 normalization upgrade (punctuation + simple plurals) that the resolve-before-create contract implies but 03-03 left at the Phase 1 baseline.

## Context
- D-15 locked: deterministic-first — normalize (case, whitespace, punctuation, simple plurals) → exact match against canonical + aliases_json; fuzzy/LLM near-miss resolution explicitly DEFERRED (do not add similarity scoring).
- D-16: pass-1 proposes alias variants; registry merges them — the accumulation loop is the designed mitigation for near-duplicates that slip past normalization.
- D-10/D-14/D-17 threshold mechanics implemented in 03-03 (`central || count_entity_sources >= min_sources`, source rows recorded for every candidate); 03-04 proved store-level no-double-count. This plan proves the page-level consequences and hardens normalization.
- Existing `normalize_name` in `store/entities.rs` (lowercase, trim, collapse whitespace) — extend in place; `resolve_entity` already matches canonical + aliases through it, so every caller (pipeline included) benefits without signature changes.
- Tests reuse the 03-03 MockProvider scripting pattern: one script per source (pass-1 JSON [+ pass-2 JSON per page that crosses]). Keep scripts minimal — threshold tests mostly assert page ABSENCE, needing no pass-2 scripts at all.
