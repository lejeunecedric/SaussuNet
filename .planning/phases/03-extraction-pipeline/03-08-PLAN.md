# Plan 03-08: Phase 3 acceptance suite + security hygiene gates

## Objective
Prove the phase goal as a whole: one executable suite mirroring the five ROADMAP success criteria, plus permanent security hygiene gates (SSRF matrix, prompt-injection containment, no-secrets-in-logs, write-funnel grep) wired into `scripts/check.sh` so regressions cannot ship silently.

## Context
- This plan adds NO features — it verifies and hardens 03-01..03-07. If an acceptance test exposes a real defect, fix it minimally in the owning module (smallest diff, note the fix in the commit).
- Every acceptance test runs the REAL queue path: `insert_job` → `spawn_workers(MockProvider)` → poll until job done → assert vault state. Zero real LLM (check.sh already forbids OpenAiCompat in test files — keep that guard green).
- Prompt-injection stance (Pitfall 12 + requirement): untrusted web content is wrapped as data (03-03 prompts), output is schema-bounded, the deterministic validator + write_page funnel is the backstop, the LLM never writes disk directly. The test demonstrates containment: a hostile source page whose scripted pass-2 output tries to cite a wiki page / link off-whitelist → rejected by the validator (03-06), recorded as `validation_rejected` proposal, nothing poisoned on disk.
- Log hygiene audit: `grep -rn 'tracing::.*payload_json\|tracing::.*api_key\|reveal()' crates/` — `SecretString::reveal()` may appear ONLY in llm/openai_compat request construction; anything else is a finding.

<threat_model>
- **SSRF (D-01/D-03):** runtime assertion of the full block-matrix (scheme allowlist http/https; loopback/RFC1918/link-local 169.254.0.0/16/CGNAT/IPv6 loopback+link-local rejected) against `assert_public_http_url` AND the HTTP endpoint (POST /ingest with blocked URL → 400, no job row).
- **Uploaded-PDF guards:** assert the 03-05 matrix at HTTP level: size cap 413, non-PDF magic 400, traversal filename sanitized — nothing outside raw/papers/ is created.
- **No secrets in logs:** audit test + check.sh grep; api_key never appears in tracing calls; job errors carry kind/reason strings only (Phase 2 D-03 pattern).
- **Prompt injection:** containment test above — hostile fixture content reaches the LLM only inside the UNTRUSTED DATA envelope (assert prompt text via MockProvider::prompts()), and off-whitelist/hallucinated output is validator-rejected before disk (PIPE-06 backstop).
- **Validator bypass:** permanent check.sh grep: no `fs::write`/`File::create` outside `vault/atomic.rs` and `vault/raw.rs` in core src (`write_atomic` is the sanctioned primitive — writer/log/index legitimately call it and are NOT flagged); pipeline writes only via `write_generated_page`. The LLM never writes to the vault directly — enforced by CI, not review.
</threat_model>
