<threat_model level="OWASP-ASVS-L1" block="high">
- **Unbounded resource use (HIGH, D-04):** pool size comes only from WorkerConfig.max_concurrency (default 1); spawn_workers spawns exactly N tasks and no per-job tasks beyond one heartbeat per in-flight job (bounded by N). Acceptance asserts observed provider concurrency <= N.
- **Prompt injection via payload_json (HIGH):** worker builds the prompt as `format!("job kind: {}\ndata:\n{}", job.kind, job.payload_json)` — payload is untrusted data placed in the user-message body, never in system instructions; provider only ever serde-parses the response. No shell, no eval, no path derived from payload in Phase 2.
- **Denial via stuck worker:** heartbeat + claim expiry bounds double-execution windows; provider call itself is bounded by the provider's own timeout (plan 02-05); reap is O(index) SQL.
- **Secret leakage:** worker logs job id/kind/error strings only — CoreError::Llm Display carries status+url, never key material (D-03).
</threat_model>

  PLANNER DECISION (record in SUMMARY): pool shape = N independent `tokio::spawn` claim loops (one task per max_concurrency slot), claim-1-per-iteration, poll-interval fallback when idle — chosen over semaphore/mpsc because durability already lives in the DB row and polling survives restart with zero extra state (PATTERNS A4 "polling fallback"). Module layout: `llm/` + `queue/` per ARCHITECTURE.md.
  1. `pub struct WorkerConfig { pub max_concurrency: usize (default 1, D-04), pub poll_interval: Duration (default 1s), pub heartbeat_interval: Duration (default 60s — D-11), pub claim_expiry: Duration (default 5min — D-11) }` with manual Default impl. Durations are injectable so tests run in milliseconds; defaults are the D-11 values verbatim — do NOT replace heartbeat with a timeout cap (CONTEXT.md Specifics forbids it).
  2. `pub fn spawn_workers(store: Arc<Store>, provider: Arc<dyn LlmProvider>, vault_id: i64, cfg: WorkerConfig) -> Vec<tokio::task::JoinHandle<()>>`: `for _ in 0..cfg.max_concurrency { tokio::spawn(worker_loop(...)) }` — exactly N handles, returned for shutdown.
  3. `async fn worker_loop(...)`: loop { `reap_expired_claims(vault_id, claim_expiry, Utc::now())`; `claim_jobs(vault_id, 1, Utc::now())`; if empty → `tokio::time::sleep(poll_interval)` + continue; else process job: spawn heartbeat task = `tokio::time::interval(heartbeat_interval)` calling `touch_claim(job.id, Utc::now())` (skip the immediate first tick); build prompt `format!("job kind: {}\ndata:\n{}", job.kind, job.payload_json)` (payload = untrusted data, threat model); `provider.generate_json(&prompt, &json!({}))` — the trait method is NON-generic and returns `serde_json::Value` (dyn-compatible `Arc<dyn LlmProvider>`; use the free `generate_json_typed` helper only when a typed struct is needed, which the worker is not); abort heartbeat; Ok → `complete_job`, Err(e) → `fail_job(job.id, &e.to_string(), Utc::now())` (D-09/D-10 transitions live in fail_job). Wrap loop body so a store panic/error logs via `tracing::error!` and continues — one bad job never kills the loop.
  4. lib.rs: add `pub mod queue;`. Do NOT touch main.rs (daemon wiring is plan 02-05).
