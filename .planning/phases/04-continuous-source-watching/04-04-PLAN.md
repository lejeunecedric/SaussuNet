# Plan 04-04: walking skeleton — poll a stub WebDAV server, enqueue a real job

## Objective
The phase's end-to-end slice: config → PROPFIND walk → diff → download → `raw/watch/` copy → durable `ingest_raw` job → worker drains it. After this plan a user-visible capability exists for the first time: a file appearing on a watched WebDAV folder becomes a queued ingestion job, proven against a stub server with zero real LLM.

## Context
- `watch/dav.rs` API (exact):
  ```rust
  pub struct DavClient { /* reqwest::Client, base: url::Url, auth: Option<(String, SecretString)> */ }
  impl DavClient {
      pub fn new(src: &ResolvedWatch) -> Result<Self>;   // 30s timeout; redirects max 5
      /// Depth:1 PROPFIND of `<base><rel>`; returns parsed entries (04-03 parser), self skipped.
      pub async fn propfind_children(&self, rel: &str) -> Result<Vec<DavEntry>>;
      /// GET with basic auth; aborts with CoreError::Fetch if body exceeds max_bytes (streaming cap, fetch.rs precedent).
      pub async fn get_bytes(&self, rel: &str, max_bytes: u64) -> Result<Vec<u8>>;
  }
  ```
  PROPFIND body verbatim from RESEARCH §protocol_notes (`<d:propfind>` with getetag/getcontentlength/resourcetype), header `Depth: 1`, `Content-Type: application/xml`, `.basic_auth(user, Some(pass))` preemptively when creds configured. Non-207 → `Err(CoreError::Dav(...))`. Body read capped at `MAX_MULTISTATUS_BYTES = 8 * 1024 * 1024` BEFORE parsing (XML-bomb/memory control). URL building: percent-encode each decoded path segment (manual encoder: keep `[A-Za-z0-9._~-]`, encode per UTF-8 byte as `%XX`), `Url::join` onto base. Error strings: `format!("{}://{}/…", scheme, host)` + rel path — never userinfo, never response bodies.
- `poll_once` v1 (in `watch/mod.rs`, exact):
  ```rust
  /// One poll of one source: walk root → diff vs watch_state → download+enqueue deltas.
  /// Returns count of enqueued jobs. Errors are returned, never panicked (caller logs WARN — D-11).
  pub async fn poll_once(store: &Store, vault: &Arc<Vault>, src: &ResolvedWatch, max_fetch_bytes: u64) -> Result<usize>
  ```
  Flow: `propfind_children("")` → map DavEntry→WalkEntry (status-404 entries ignored in v1 — sync lands 04-07) → `list_watch_rows` → StateEntry → `diff_walk(walk, state, &src.extensions)` → for Added/Changed file deltas: `get_bytes(rel, max_fetch_bytes)` → sha256 (hex, sha2 crate) → `.md`/`.txt`: `submit_raw(...)`; `.pdf`: `submit_pdf(...)` → **then** `upsert_watch_row(vault_id, source_id, path, false, etag, size, Some(sha), now_rfc3339)` (order is the crash-safety rule — comment it). `record_sync_poll(vault_id, source_id, Some(now), None)` at the end of a successful poll. Directories: upsert `is_dir=true` rows (etag/size NULL) for state bookkeeping, never enqueued.
- `pipeline/mod.rs` additions: `pub const JOB_KIND_INGEST_RAW: &str = "ingest_raw";`; `IngestRawPayload { raw_path, source_id, filename }` (same serde shape as IngestPdfPayload); `pub async fn submit_raw(store: &Store, vault: &Vault, bytes: &[u8], filename: &str, source_hint: &str, max_bytes: u64) -> Result<(i64, String)>` — mirror `submit_pdf` (pipeline/mod.rs:143): size cap, extension must be md|txt, `sanitize_component(stem)`, **`write_raw` (not write_raw_binary) with subdir `Some("watch")`** and `RawFrontmatter { source_url: source_hint, ingested, sha256 }` so text copies carry provenance like web pages; payload `{raw_path, source_id: raw_rel, filename}`; `insert_job(JOB_KIND_INGEST_RAW)`. Worker arm in `handle_job`: read raw copy with the same `rel.starts_with("raw")` path guard `ingest_pdf` uses, compute sha256 of the file bytes, cheap `get_source_sha256` no-op (skip if equal — free defense for re-queued jobs), `set_source_sha256`, then `run_extraction_passes(...)` exactly as the ingest_pdf tail does (read its call site ~pipeline/mod.rs:355).
- Stub server (`tests/watch_webdav.rs`, pattern: `tests/llm_provider_thinking.rs` one-shot stub — but STATEFUL): `struct StubFile { bytes: Vec<u8>, etag: String }`; tree `Arc<Mutex<HashMap<String /*decoded rel path, dirs end '/'*/, StubFile>>>`; request log `Arc<Mutex<Vec<(String method, String path, Option<String> depth, String body)>>>`; `std::thread` accept-loop, per-connection `std::io::Read` until `\r\n\r\n` + Content-Length. Handlers: PROPFIND → 207 with self first then one-level children (resourcetype/getetag/getcontentlength per 04-03 fixtures); GET → bytes + `ETag` header (404 if absent); POST → 400 (sync unsupported — exercises the D-05 fallback path later). `StubHandle` exposes `insert(path, bytes, etag)`, `remove(path)`, `set_etag(path, etag)`, `requests()`. Tests build `ResolvedWatch` through `toml::from_str::<FileConfig>` + `resolve()` (exercises 04-01 end-to-end) with url = stub base, interval 300s, extensions default.

<threat_model>
- **HIGH — credential leakage via URLs/errors:** creds ONLY via `.basic_auth()` from `SecretString::reveal()` at request-build time; 04-01 already rejects userinfo URLs. `DavClient` error Display = scheme+host+path only; test `error_string_has_no_password` asserts a failed request's error string contains neither the stub password nor `Basic` header material. BLOCKING: any error path that interpolates a full request URL with userinfo or an Authorization header fails the plan.
- **HIGH — untrusted server responses (XML bomb / memory DoS):** response bodies size-capped BEFORE parse (8 MiB multistatus cap; `max_fetch_bytes` download cap, streaming abort like fetch.rs); roxmltree does no DTD/entity expansion (04-03). Test: stub returns an oversized body → poll_once errors, no hang.
- **Path traversal via crafted hrefs into raw/ writes:** hrefs are never fs paths — the only disk write is `write_raw`'s `sanitize_component` slug (folds to `[a-z0-9-]`, refuses escapes). Test: stub serves `../../evil.md` → poll enqueues with a sanitized slug, nothing written outside `raw/watch/`.
- **Prompt injection:** unchanged surface — downloaded bytes enter the pipeline exactly as URL/PDF bytes do; Phase 3 validator + write funnel is the backstop. No new LLM trust boundary here.
- **Depth-cap DoS:** v1 walks only the root (single PROPFIND); full-walk cap enforced in 04-05 (T4).
</threat_model>
