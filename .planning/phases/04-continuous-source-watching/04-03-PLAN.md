# Plan 04-03: pure watch logic — multistatus parser + diff (no I/O)

## Objective
The two brain pieces of the poller, built test-first with zero network: an RFC 4918 multistatus / RFC 6578 sync-report parser and the pure walk-vs-state differ. After this plan, given any recorded server response and any persisted state, the system can already answer "what changed" — 04-04 just wires HTTP and the queue around it.

## Context
- New module `crates/saussunet-core/src/watch/` (layout from RESEARCH §Recommended module layout): `mod.rs` (declares `pub mod diff; pub mod multistatus;` — 04-04 adds `pub mod dav;` and poll_once here), `lib.rs` gains `pub mod watch;`.
- New dep: `roxmltree = "0.21"` in root `[workspace.dependencies]` + `roxmltree = { workspace = true }` in core `[dependencies]`. NOT quick-xml (pull-parser event state machine ≈3× the code for this use), NOT reqwest_dav (reqwest 0.13 pin conflict — dispositive).
- Parser API (exact):
  ```rust
  pub struct DavEntry {
      pub path: String,            // decoded, root-relative, '/' separators, no leading '/', no trailing '/'
      pub etag: Option<String>,    // verbatim incl. W/"…" weak prefix
      pub size: Option<i64>,       // getcontentlength (absent on collections)
      pub is_collection: bool,     // resourcetype <collection/> OR trailing-slash href
      pub status: u16,             // per-item <d:status> code; 200 when absent (plain PROPFIND)
  }
  /// `root_path` = the walked collection's percent-ENCODED URI path (from the request Url),
  /// used to relativize hrefs. Collection-self (href == root) is SKIPPED (Pitfall: Depth:1 includes self).
  pub fn parse_multistatus(xml: &str, root_path: &str) -> Result<Vec<DavEntry>>
  pub fn extract_sync_token(xml: &str) -> Option<String>   // trailing <d:sync-token> text, trimmed
  ```
  Parsing rules (RESEARCH §protocol_notes): namespace-aware (`namespace_uri() == Some("DAV:")`); a prop counts only under a `<propstat>` whose `<status>` line contains `" 200 "`; `<getetag>`/`<getcontentlength>`/`<resourcetype>` only; href percent-decoded once (UTF-8), then prefix-stripped against the decoded root; per-item `<d:status>` parsed for sync reports (404 → removed marker entry with status 404).
- Diff API (exact — plain structs so it is testable without DB or HTTP):
  ```rust
  pub struct WalkEntry { pub path: String, pub etag: Option<String>, pub size: Option<i64>, pub is_dir: bool }
  pub struct StateEntry { pub path: String, pub etag: Option<String>, pub size: Option<i64>, pub is_dir: bool, pub sha256: Option<String> }
  pub enum WatchDelta { Added(WalkEntry), Changed(WalkEntry), Removed(StateEntry), Skipped(WalkEntry) }
  /// walk = full set from a COMPLETED walk (caller guarantees; removals must never run on partial walks — Pitfall 3).
  /// allowlist = lowercase dotless extensions (D-08). Unchanged (etag AND size equal) → no delta.
  /// Any etag difference → Changed (sha256 gate downstream decides — never trust etag alone, D-07).
  /// is_dir entries → no delta (dirs are state bookkeeping only, never enqueued).
  /// Skipped = Added/Changed whose extension ∉ allowlist (poller logs once, 04-05).
  pub fn diff_walk(walk: &[WalkEntry], state: &[StateEntry], allowlist: &[String]) -> Vec<WatchDelta>
  ```
- Conversion helpers `impl From<&DavEntry> for WalkEntry` and `impl From<crate::store::WatchRow-ish>` — keep diff.rs free of store imports; poll_once maps rows → StateEntry.
- Sample fixtures to embed as string constants in tests: a realistic 207 (self + `note.md` + `papers/` collection + `a%20b.md` + `caf%C3%A9.txt` + a prop whose propstat is 404), a sync-report 207 (one 200-item, one 404-item, trailing sync-token).

<threat_model>
- **Untrusted XML (XML bomb / entity expansion):** roxmltree performs no DTD fetching and errors on undefined entities — billion-laughs expansion is inert. Residual memory risk is bounded by the caller's response size cap (enforced in 04-04 dav.rs before parse — recorded there as a blocking threat control). Parser tests include a nested-but-small document; no recursive-parse config is enabled.
- **Path traversal via crafted hrefs:** parsed `path` values are opaque DB/log keys only; this plan writes nothing to disk. The fs boundary is `write_raw`'s `sanitize_component` (04-04). Test asserts a `../../etc/passwd` href parses to a harmless relative key string, never an absolute path.
- **Credentials:** none in scope here (parser sees response bodies only). Enforced in 04-04 (request building).
- SSRF / prompt injection: N/A — no network, no LLM. Enforced in 04-04 (client) and Phase 3 (pipeline funnel).
</threat_model>
