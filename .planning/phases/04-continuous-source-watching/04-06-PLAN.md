# Plan 04-06: daemon lifecycle — interval loop, restart-resume proof

## Objective
Wire the poller into the daemon's life: each configured source gets its own interval task that polls on startup and forever after, survives failures silently, and — the phase's headline claim — a full server restart resumes watching with zero re-scan, proven on a file-backed SQLite DB.

## Context
- `spawn_watcher` (exact, in `watch/mod.rs` — mirrors the `queue/mod.rs` worker_loop shape):
  ```rust
  pub fn spawn_watcher(
      store: Arc<Store>,
      vault: Arc<Vault>,
      src: ResolvedWatch,
      max_fetch_bytes: u64,
  ) -> tokio::task::JoinHandle<()> {
      tokio::spawn(async move {
          // first-poll jitter (RESEARCH open Q5): deterministic, no rand
          let jitter = { use std::hash::{Hash, Hasher}; let mut h = std::collections::hash_map::DefaultHasher::new();
              src.source_id.hash(&mut h); let ms = h.finish() % 5000;
              std::time::Duration::from_millis(ms.min((src.interval / 10).as_millis() as u64)) };
          tokio::time::sleep(jitter).await;
          let mut tick = tokio::time::interval(src.interval); // first tick fires immediately (D-10)
          loop {
              tick.tick().await;
              if let Err(e) = poll_once(&store, &vault, &src, max_fetch_bytes).await {
                  // D-11: WARN only — poll_once errors are pre-sanitized (no creds, no bodies)
                  tracing::warn!(source = %src.source_id, "watch poll failed: {e}");
              }
          }
      })
  }
  ```
- `main.rs boot()` insertion point: after the `daemon_drains_queue` worker-pool block (~line 165), before the axum listener:
  ```rust
  // Phase 4 (D-12): one watcher task per configured [[watch]] source. Runs even

  ```
  and in the ctrl_c teardown: `for h in watch_handles { h.abort(); }` alongside the existing `handles` loop. NOTE: the worker block currently MOVES `store`/`vault`/`provider` into `spawn_workers` — restructure to clone Arcs for the watcher block (keep WR-03 gating semantics for workers exactly as-is). `ResolvedWatch` must be `Clone` (add derive if 04-01 didn't).
- T6 restart test MUST use file-backed SQLite (`Store::connect(&tempdir.path().join("saussunet.db"))`) — `connect_memory` resets on drop and would fake a pass (RESEARCH §Test Strategy). Vault also tempdir-backed; `Vault::init_fs` after connect.
- T5 test uses `spawn_watcher` directly with a hand-built `ResolvedWatch { interval: Duration::from_millis(10), ..}` + tokio test runtime; observe via `StubHandle::requests().len() >= 2` after ~150 ms sleep (jitter cap keeps startup <1 ms).

<threat_model>
- **Credential leakage:** the loop's WARN carries only poll_once's pre-sanitized error strings (04-05 test proves password absence from last_error; same strings reach this log line). No new error formatting here.
- **Resource exhaustion:** one task per config entry (config is operator-authored, bounded); interval has no backlog (tokio interval skips missed ticks rather than queueing). A hung poll is bounded by DavClient's 30 s reqwest timeout (04-04).
- **Silent watcher death:** a panic inside spawn_watcher's task would stop a source invisibly. Mitigation: JoinHandle is kept; acceptable for v1 (same posture as worker pool) — document in code comment; Phase 5 UI surfaces last-poll status.
- SSRF / prompt injection / traversal: N/A — no new I/O surface; enforced in 04-04/04-05.
</threat_model>
