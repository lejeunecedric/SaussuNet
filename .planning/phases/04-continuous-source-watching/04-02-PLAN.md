# Plan 04-02: migration 0009 + `watch_state` store (persistence substrate for SRCC-02)

## Objective
Give the watcher a durable per-file memory (etags, sizes, sha256, sync token latch) in SQLite so a restart resumes with zero re-scan. After this plan the state layer the poller diffs against exists and is tested — the visible slice completes in 04-04 when a poll actually reads/writes it.

## Context
- Next free migration number is **0009** (verified: `migrations/` tops out at `0008_proposal_reason_validation.sql`). Migrations auto-apply via `sqlx::migrate!` in `Store::connect` — no code wiring.
- Exact schema (from RESEARCH §Migration 0009 — use verbatim):
  ```sql
  -- 0009_watch_state.sql — per-file watcher state for WebDAV sources (SRCC-02).
  CREATE TABLE IF NOT EXISTS watch_state (
      vault_id   INTEGER NOT NULL REFERENCES vaults(id) ON DELETE CASCADE,
      source_id  TEXT NOT NULL,           -- watch source id (config url, verbatim)
      path       TEXT NOT NULL,           -- decoded path relative to watched root, '/' separators, no leading '/'
      is_dir     INTEGER NOT NULL DEFAULT 0,
      etag       TEXT,
      size       INTEGER,
      sha256     TEXT,                    -- digest of last ingested bytes (D-07 gate)
      last_seen_at TEXT NOT NULL,        -- last poll that observed it (removal detection)
      PRIMARY KEY (vault_id, source_id, path)
  );
  ALTER TABLE sync_state ADD COLUMN sync_unsupported INTEGER NOT NULL DEFAULT 0;
  ```
- Store API shape (pattern: `store/sync_state.rs`; sqlx 0.8, `FromRow`, `crate::error::Result`):
  ```rust
  pub struct WatchRow { pub vault_id: i64, pub source_id: String, pub path: String,
                        pub is_dir: bool, pub etag: Option<String>, pub size: Option<i64>,
                        pub sha256: Option<String>, pub last_seen_at: String }
  impl Store {
      pub async fn upsert_watch_row(&self, vault_id: i64, source_id: &str, path: &str,
          is_dir: bool, etag: Option<&str>, size: Option<i64>, sha256: Option<&str>,
          last_seen_at: &str) -> Result<()>;
      pub async fn list_watch_rows(&self, vault_id: i64, source_id: &str) -> Result<Vec<WatchRow>>;
      pub async fn delete_watch_row(&self, vault_id: i64, source_id: &str, path: &str) -> Result<()>;
      /// Diff-and-swap after a COMPLETED walk (D-11 atomicity): one transaction —
      /// DELETE all rows for (vault_id, source_id) then insert the fresh set.
      pub async fn replace_watch_rows(&self, vault_id: i64, source_id: &str, rows: &[WatchRow]) -> Result<()>;
  }
  ```
- sync_state additions (same plan, `store/sync_state.rs`): add `sync_unsupported: bool` to the `SyncState` FromRow struct + its SELECT list; add `record_sync_poll(vault_id, source_id, last_poll_at: Option<&str>, last_error: Option<&str>)` (upsert touching ONLY those two columns — token/etag/sha256 untouched), `set_sync_token(vault_id, source_id, token: Option<&str>)`, `set_sync_unsupported(vault_id, source_id, bool)`. All upsert-safe (INSERT ... ON CONFLICT DO UPDATE of the owned columns only, mirroring `set_source_sha256`'s pattern at sync_state.rs:71).
- `store/mod.rs`: declare `mod watch_state;` alongside the other submodules.

<threat_model>
- **Credential leakage:** N/A — no credentials touch this schema (source_id is the credential-free url; userinfo urls were rejected in 04-01). Enforced upstream by 04-01.
- **Untrusted input:** `path` values originate from a (trusted-per-D-03) WebDAV server's hrefs, but are stored only as opaque DB keys — never used as filesystem paths (fs writes funnel through `write_raw`'s slug sanitizer in 04-04). All access is parameter-bound sqlx — no string interpolation.
- **DoS:** row count is bounded by the walked tree (depth-capped in 04-05); no unbounded growth path here.
- Prompt injection / SSRF: N/A here — enforced in 04-04 (client) and Phase 3 (pipeline).
</threat_model>
