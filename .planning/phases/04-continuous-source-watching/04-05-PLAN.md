# Plan 04-05: full walk semantics — depth cap, removals, sha256 gate, quiet failures

## Objective
Make the poller production-honest: the whole tree is walked under the depth cap, changed files re-enqueue, weak-etag churn is absorbed by the sha256 gate, removals are logged and pruned (never touching vault pages), failures record `last_error` without spamming, and a no-op poll is completely silent. This completes success criteria 1 and 3 for the PROPFIND path.

## Context
- BFS walk inside `poll_once` (replaces 04-04's root-only call): `let mut queue = vec![(String::new(), 0usize)]` of `(rel, depth)`; pop front, `propfind_children(rel)`; for each entry: files → walk set; collections → record dir row + push `(child_rel, depth + 1)` **only while `depth + 1 <= src.depth_cap`** (root = depth 0; cap 4 ⇒ PROPFINDs at depths 0..4). Every request uses the existing `propfind_children` (always `Depth: 1` — never anything else, SRCC-01). Track `walk_complete: bool` — false if any PROPFIND errored; on error: keep entries collected so far, set `last_error = Some(sanitized error string)` (scheme+host+path only, D-02 hygiene).
- Diff pass (04-03 `diff_walk`): on a complete walk pass the full state; on a partial walk pass an EMPTY state for the Removed classification (i.e. compute Removed only when `walk_complete`) — additions/changes still flow from the partial set.
- sha256 gate before enqueue: after `get_bytes` + hex sha256, compare with the matching `StateEntry.sha256` — equal ⇒ `upsert_watch_row` (fresh etag/size, same sha256) and NO job (T10). Unequal ⇒ existing submit path + row upsert after insert_job (04-04 crash-safety order unchanged).
- Removal pass (complete walks only): `Removed(state_entry)` deltas where `!is_dir` ⇒ `delete_watch_row` + collect log line `removed: <path> (<source_id>)`. Removed dirs: delete row silently. Vault pages untouched (D-09 — assert by test, not just by absence of code).
- log.md discipline: one `vault::log::append_entry(vault, "Watch", &lines)` call per poll, only if `lines` non-empty. Line formats: `added: <path>`, `changed: <path>`, `removed: <path>`, `skipped (extension not allowlisted): <path>`. Paths sanitized: replace `'\r'`/`'\n'` with `' '` (log-injection guard). Skip deltas log ONLY when no prior state row exists for the path (then upsert the marker row with etag/size, sha256 NULL).
- Failure bookkeeping: success ⇒ `record_sync_poll(vault_id, source_id, Some(now), None)`; failure ⇒ `record_sync_poll(..., Some(now), Some(&sanitized_err))` then `Err`. `poll_once` still never logs (loop owns WARN — 04-06).
- Stub additions: `StubHandle` gains depth-capable tree (already path-keyed — insert `a/b/c/deep.md` auto-creates intermediate dirs in PROPFIND synthesis), a `fail_next_propfind: AtomicBool` (or `fail_paths: HashSet<String>`) knob for T7, and the request log already records method+path+depth for T4.

<threat_model>
- **HIGH — partial-walk removal storm (availability/data):** removals computed ONLY from a walk that completed every level without error (Pitfall 3). One network blip must never log every file as removed or wipe state. Enforced by `walk_complete` gate + test `poll_failure_records_last_error` asserting zero removal log lines after a failed walk.
- **HIGH — credential leakage in last_error:** `last_error` strings are built from sanitized DavClient errors (scheme+host+path only); test asserts the stub password is absent from `sync_state.last_error` after a forced auth failure.
- **Log injection via crafted filenames:** untrusted server paths are newline-stripped before entering log.md (one forged log line per poll is the attack). Test: stub file named `evil.md\nINJECTED` → log.md contains no extra entry header (assert `entry_count` unchanged / no `\nINJECTED` line).
- **DoS (deep/wide trees):** depth_cap bounds PROPFIND fan-out (T4); download size cap from 04-04 bounds per-file memory.
- Prompt injection / SSRF: unchanged — Phase 3 funnel + D-03 trusted-operator decision.
</threat_model>
