# Plan 04.1-03 Summary: wikilink resolver + footnote citations

## What was built

**Task 1 — wikilink resolver + markdown-link floor (RED→GREEN)**
- `okf.rs`: `build_slug_map(vault, store, own_rel) -> HashMap<stem, (title, /path.md)>` from exactly the four planned sources: index.md entries (same line discipline + traversal guards as `validate::index_entry_map`, title recovered from the entry text), `page_registry` rows (registry title authoritative), entity `canonical_name` + `page_path` stem, and the page's own stem (`entry().or_insert` — never overwrites). Paths come only from registry/index values already validated against `PAGE_DIRS`; slugs containing `..` are rejected from the map.
- `okf.rs`: `rewrite_wikilinks(body, &map)` — plain `find("[[")` walk mirroring `count_outbound_wikilinks`: bare → `[title](/path.md)`, aliased → `[alias](/path.md)` with `]` stripped from alias text (injection guard), `[[dir/path]]` resolves via last segment (`.md` stripped), `#heading` anchors stripped, `![[embed]]` kept verbatim, unresolvable → `[slug](/slug.md)` with `..`/`/` sanitized out (traversal can never render), root-relative form always (D-11).
- `frontmatter.rs`: `count_outbound_markdown_links` — plain scan of `](/` per okflint `MD_LINK` (`okflint.py:39`), HashSet-deduped by target; `](http://…)` and bare-relative `](x.md)` not counted.
- `writer.rs` `write_generated_page`: after the unchanged `validate_generated_page` gate — split, `rewrite_wikilinks`, enforce ≥2 markdown links (error names "markdown links"), rejoin, then the existing rebuild → `write_page`. The raw-existence gate still runs on the ORIGINAL `^[...]` markers (order preserved).
- `write_page` floor widened to `wikilinks < 2 && markdown links < 2` (see Deviations 1); human-path wikilink semantics preserved (existing pin "at least 2 outbound" still green).

**Task 2 — footnote citations keyed to sources[].id (RED→GREEN)**
- `okf.rs`: `rewrite_citations(body, &sources) -> (body_with_markers, definitions)` — first-seen `^[` walk (extract_provenance shape); id looked up by `resource` path from the sources[] maps (never recomputed; stem fallback only for direct calls with mismatched sources); all occurrences of one target share one marker; definitions `[^id]: <title-or-source_url>` joined in first-appearance order, no trailing newline.
- `rebuild_frontmatter`: immediately after `fm.sources = sources_entries(...)`, rewrites markers and appends the definition block once at body end (`\n\n` separated) — footnote keys and `sources[].id` are literally the same values (D-12/D-14). No v0.1 citations heading is emitted anywhere (`grep -rn '# Citations' crates/saussunet-core/src/` → 0).
- `okf.rs`: `count_broken_links(root)` INFO helper (okflint.py:143-151 port) — walks .md files, counts distinct missing `](/…)` targets; consumed by migrate --verify (04.1-05), never fails a write (D-20/D-22).

## Deviations

1. **`write_page`'s wikilink floor was widened, not left untouched.** The plan text said "keep write_page's human-path check as-is", but the wrapper delegates to `write_page`, and a rewritten generated page has ZERO wikilinks — the untouched check would reject every generated page. Minimal widening: reject only when BOTH `count_outbound_wikilinks < 2` AND `count_outbound_markdown_links < 2` (error message keeps the "at least 2 outbound" substring the human-path test pins). Human pages with wikilinks behave byte-identically; the generated path still gets its own markdown-specific floor error earlier in the funnel.
2. **Footnote id = raw path stem (e.g. `2026-10-30-foo`), not the `raw-`-prefixed example in D-12's prose.** The binding rule (must_haves D-14, Task 2 GREEN text) is "footnote ids are exactly the sources[].id values built in plan 04.1-01" — and wave-1 `sources_entries` ids are stems (pinned by `sources_entries_shape_unit`). The D-12 example string was illustrative; keyed equality wins.
3. **`rewrite_citations` runs inside `rebuild_frontmatter`, not as a separate wrapper step.** Task 2 GREEN explicitly allows "as part of the rebuild step": sources are computed there, and keying footnotes to them requires the same scope. Funnel order (links → citations → frontmatter serialize → check_page) matches PATTERNS §4.
4. **T5 extension added as a new test fn** (`sources_footnotes_keyed`) in okf_frontmatter.rs rather than editing `sources_entries_shape` in place — keeps wave-1's pin byte-stable while adding the keyed-id assertions.
5. **`build_slug_map` re-parses index entry lines locally** (title + path) instead of reusing `index_entry_map` (which returns stem→path only, no title). Same line discipline and guards, duplicated because validate.rs was not in this plan's files_modified. A future consolidation could return titles from `index_entry_map`.

## Decisions

- Floor enforcement is per-path: wrapper enforces the markdown floor with a markdown-named error (acceptance criterion); `write_page` keeps a combined backstop so human pages are unaffected and VLET-02 (single mutation entry) holds without a bypass flag.
- `rewrite_citations` returns `(body, definitions)` instead of writing the tail itself — the caller (rebuild) owns body assembly, so a page with zero markers gets its body untouched (D-14 zero-definitions case falls out naturally).
- Markers pointing outside `raw/` are left verbatim by `rewrite_citations` (defense in depth): the PIPE-06 gate rejects such pages upstream, and silently rewriting them would hide validator bugs.
- `count_broken_links` counts DISTINCT missing targets across the whole tree (okflint aggregates per-bundle), INFO-only per D-20.

## Lessons

- serde_yml 0.0.13: `Mapping::get("id")` accepts `&str` for reads (wave-1 note was about `insert` needing `String` keys) — reads via `.get("k").and_then(|v| v.as_str())` work directly.
- The PIPE-06 gate whitelist and the resolver slug map are near-identical sets, so anything that passes the gate resolves — EXCEPT entity `canonical_name`s without `page_path` (whitelisted but pathless): they render the broken form, which is exactly D-10's "broken links are a feature".
- `upsert_entry(vault, "Concepts", "Meta", ...)` writes path `/concepts/Meta.md` (stem case preserved) — fixture expectations must use the PATH's stem casing, not a lowercased guess.
- The known `pipeline_url::unknown_kind_dead_letters_with_error_retained` SQLITE_BUSY flake reproduced again this run (failed in check.sh's suite AND on first isolated run, passed on second isolated run) — intermittent even isolated; do not chase.
- A comment containing the literal `# Citations` trips the plan's own acceptance grep — keep retired-format names out of source comments verbatim.
