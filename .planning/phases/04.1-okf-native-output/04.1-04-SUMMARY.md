## Deviations

   Task 2 text said validate.rs passes subtypes into `check_page`'s vocabulary
   parameter, but the actual `check_page` call site is `okf::rebuild_frontmatter`
   (the hook comment 04.1-01 left is there), and T3 additionally exposed that

   answering `"concept"` per the prompt wording.

## Decisions

- The subtype reaches disk through the FRONTMATTER (assemble_page emits the folded
  capitalized value), not via a pre-write registry update: the registry row has no
  `page_path` on first write, so rebuild's registry fallback could not see it; the
  first branch of the rebuild type step (value already in the union vocab) keeps it.
- `parse_entity_subtypes` failure is fatal at write time (`?`), mirroring
  parse_tag_taxonomy's fail-loud posture (threat model: named error, not silent
  acceptance). Pre-04.1 vaults get their SCHEMA.md updated by migrate (04.1-05).
- The registry stores the folded value parsed back off the assembled page rather
  than re-deriving it in gate_and_write — one fold site (assemble_page), so page and
  registry cannot disagree.
- SCHEMA.md seed carries minimal frontmatter (`type: Schema`, `title`) — enough for
  the MoriNet 80% denominator; nothing parses SCHEMA.md frontmatter yet, and
  phase1_acceptance explicitly excludes SCHEMA.md from its parse check.

## Lessons

- The type gate exists in THREE places (validate_generated_page, rebuild_frontmatter's
  check_page, write_page step 2) — a vocabulary change must touch all three or the
  page dies at the last one with a Frontmatter error that bypasses the
  Validation-proposal branch (job fails instead of the page being proposed).
- `CandidateKind` derives PartialEq, so `kind == CandidateKind::Entity` reads better
  than matches for the fold branch; the fold must run BEFORE the PAGE_TYPES check or
  capitalized subtypes would fold away on the legacy lowercase membership test.
- The known `pipeline_url::unknown_kind_dead_letters_with_error_retained`
  SQLITE_BUSY flake fired once during the first full-suite run (0 failures on the
  three subsequent --no-fail-fast runs, including two consecutive clean 319/0 runs)
  — per the wave-3 note, not chased.
- A seed template inside `format!(r#"..."#)` cannot contain literal `{}` braces —
  the D-06 template uses nested block YAML (no braces) so it fits without escaping.
