# Plan 04.1-01: OKF frontmatter core + conformance gate seed

## Objective
As a vault consumer (MoriNet, a stranger cloning the vault), I want every page SaussuNet writes to carry conformant OKF v0.2 frontmatter — descriptive `type`, `title`, non-empty `description`, offset-bearing timestamps, `generated: {by: process:saussunet/<version>, at}`, honest `sources[]` — so that the vault reads as an OKF bundle from the first ingest, and the write-path gate refuses any page that would break §11 conformance before it touches disk.

**User story slice:** ingest a URL (MockProvider in tests) → the page on disk already has OKF frontmatter and the gate rejects malformed pages. Links/citations are still llm-wiki form in this slice (plans 04.1-02/03).

## Context
- Insertion point: `write_generated_page` wrapper (`writer.rs:300-308`, verbatim in PATTERNS §4). The OKF rebuild step goes between `validate::validate_generated_page` and `write_page` — `write_page` (human/CLI path, wikilink floor at `writer.rs:111`) stays untouched in this plan.
- `frontmatter::serialize` (`frontmatter.rs:135-176`) is a flat string pusher; RESEARCH anti-pattern bans hand-rolled nested keys — build `serde_yml::Value::Mapping` (in-tree precedent: `frontmatter.rs:50`, `ghash.rs:154-161`) and keep the `scalar()` quoting guard (`frontmatter.rs:180-197`) for extension keys.
- **No regex crate** (PATTERNS §12): ACTOR and ISO_OFFSET are fixed-shape character scans per the plain-scan precedent (`count_outbound_wikilinks`, `frontmatter.rs:209-228`). Port shapes verbatim from `okflint.py:33-38` (read it).
- Paired change flagged by PATTERNS §3.2: `index_section()` (`writer.rs:39-47`) keys off the old lowercase types — repoint it at the directory of the rel_path (sections keep the four llm-wiki names, smaller-diff discretion choice).
- Existing tests asserting lowercase `type` (`frontmatter.rs` tests, pipeline fixtures) must be updated to the new vocabulary in the same commit; `scripts/check.sh` green is the gate.
- MoriNet cross-check (Pitfall 5): every generated page carries `generated` + `sources`, so MoriNet's version guess reads `"0.2"` once the 80% ratio holds.

<threat_model>
- **Honesty-rule violation (HIGH, block):** the writer must never emit `verified`, `status`, `stale_after`, or invented credibility fields (D-05, PROJECT.md Key Decisions). Test `honesty_no_trust_fields` asserts those keys are absent from every serialized page and that `sources[]` keys are exactly the D-13 set.
- **Gate bypass (HIGH, block):** all §11 checks run deterministically BEFORE any disk write, inside the existing funnel; atomic writes only (write-funnel grep in `scripts/check.sh:28-36` must stay green — no `fs::write`/`File::create` added in core outside `vault/atomic.rs`/`vault/raw.rs`).
- **YAML injection via frontmatter values (MED):** the `scalar()` quoting guard is retained for every emitted scalar; a title containing `:`/newline cannot forge a frontmatter key (test asserts round-trip through `split`+`parse`).
- **Secret leakage:** none — no credentials flow through this module; error strings carry page-relative paths and rule names only.
</threat_model>
