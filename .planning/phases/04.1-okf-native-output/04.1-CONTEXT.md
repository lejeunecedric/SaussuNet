<domain>
## Phase Boundary

The vault SaussuNet writes **is** an OKF bundle: `vault::writer` emits conformant
frontmatter (`type`/`title`/`description`/`timestamp`/`generated`/`sources`),
bundle-relative markdown links instead of `[[wikilinks]]`, and per-claim
provenance in the OKF notation; `index.md` and `log.md` follow OKF §8/§9; the
write-path validator enforces bundle conformance on every page before it touches
disk; and `saussunet migrate-okf` converts an existing llm-wiki vault in place.

This is the **output format layer only**. No bundle-wide lint reporting, review
queue or UI (Phase 5), no MCP endpoint (Phase 6), no new source kinds, no trust
fields without evidence, no path-layout migration of `entities/`/`concepts/`/
`comparisons/`/`queries/` (storage layout is unchanged — only what is written
inside the files changes).

Requirements: OKF-01, OKF-02, OKF-03, OKF-04, OKF-05, OKF-06, OKF-07 (7).

**Superseded contracts (already noted in ROADMAP):** the "≥2 outbound wikilinks"
floor survives but counts markdown links; Phase 5 LINT-01 "broken wikilinks"
reads as "broken markdown links".

<decisions>
## Implementation Decisions

### Spec target (locked by user 2026-11-18)

- **D-01:** Declare **OKF v0.2** (`okf_version: "0.2"` in the root `index.md`), as
  locked in PROJECT.md and ROADMAP — the whole family is on 0.2 (B3Wiki declares
  `"0.2"`, MoriNet `src/okf.rs` guesses `"0.2"`). **But write to the v0.3-safe
  subset** so a later version bump is a one-line change: bundle-relative `/path.md`
  links only (v0.3 §6.2 changed bare-path resolution), footnotes for per-claim
  attribution, every timestamp with an explicit UTC offset (no date-only values),
  `okf_version` quoted, no custom YAML tags, no duplicate frontmatter keys.
  ⚠ **v0.3 was published the day this phase was inserted (2026-11-18)** and the spec
  repo moved to `github.com/open-knowledge-format/open-knowledge-format`. If the
  user prefers to target 0.3 outright, the deltas that matter here are: conformance
  no longer requires frontmatter in every `.md` (v0.3 §3.2/§11 — see D-15), root
  `index.md` may carry `title`/`description`/`license` (§8.1), and `superseded_by`
  exists (§5.4).

### Type vocabulary (OKF-01)

- **D-02:** Emitted `type` values are **descriptive and capitalized**, derived from
  the page directory: `concepts/` → `Concept`, `comparisons/` → `Comparison`,
  `queries/` → `Query`, `raw/` → `Source` (D-15). Directory names themselves do
  not change.
- **D-03:** `entities/` pages get a descriptive subtype supplied by the pass-2 LLM
  (`page_type` in the pass-2 schema) constrained to a vocabulary **declared in the
  vault's own SCHEMA.md** (e.g. `Person`, `Organization`, `Tool`, `Place`, `Event`,
  `Work`); unknown or absent folds to `Entity` (tolerant-parse rule from Phase 2
  D-05 — a bad subtype never kills the pass). The subtype is stored in
  `entity_registry.page_type` and enforced deterministically at write time.
- **D-04:** The 4-value llm-wiki `PAGE_TYPES` list (`frontmatter.rs:19`) stops
  being the emitted `type`. `PAGE_DIRS` (storage layout) is unchanged.
- **D-05:** llm-wiki extension keys survive verbatim as OKF extension keys (§4.1
  consumers MUST preserve unknown keys): `tags`, `confidence`, `contested`,
  `contradictions`, `protected`, `gen_hash`, and — for one release, for Obsidian
  and llm-wiki readers — `created`/`updated`. **Never** emit `verified`, `status`
  or `stale_after` (honesty rule, locked in PROJECT.md).

### Frontmatter shape (OKF-01)

- **D-06:** Key order on a generated page: `type`, `title`, `description`, `tags`,
  `timestamp`, `generated: { by: process:saussunet/<version>, at: <ISO UTC> }`,
  `sources: [...]`, then extension keys. `<version>` = `CARGO_PKG_VERSION`; the
  actor follows the §7 convention.
- **D-07:** `description` becomes a **first-class pass-2 output** — the LLM writes
  the one-line summary (OKF-MAPPING lesson #4). Fallback when the model omits it:
  first sentence of the body. A generated page never ships an empty description.
- **D-08:** `timestamp` = last content change (maps from llm-wiki `updated`),
  `generated.at` = when this version was written (maps from `created`). Both ISO
  8601 with explicit UTC offset.

### Links (OKF-02)

- **D-09:** The LLM **keeps emitting `[[slug]]` wikilinks**; a deterministic
  writer pass resolves slug → bundle-relative path and rewrites to
  `[Title](/path.md)` before validation. The resolver reuses exactly today's
  whitelist source (index.md stems ∪ entity registry `page_path` stems ∪ own
  stem). The LLM is never asked to produce paths — path hallucination is not a
  risk we take on.
- **D-10:** Unresolvable slug → `[slug](/slug.md)`, kept as a broken link (§6.1
  "broken links are a feature"). The ≥2 outbound-link floor survives, counted on
  markdown links.
- **D-11:** Root-relative `/path.md` form everywhere (valid under both v0.2 and
  v0.3); never a bare relative path.

### Citations and `sources[]` (OKF-03 — locked by user 2026-11-18: footnotes)

- **D-12:** `^[raw/x.md]` markers become **markdown footnotes keyed to
  `sources[].id`** (`[^raw-2026-10-30-foo]` in the body, `[^raw-2026-10-30-foo]:
  <title>` definitions at the end), per v0.2 §5.1 and v0.3 §4.2 (body dialect =
  CommonMark + GFM tables + `[^label]` footnotes). **No `# Citations` body
  section** — that is the v0.1 form v0.2 §13.1 explicitly supersedes.
  ⚠ This **contradicts ROADMAP success criterion 2 / OKF-03 as written** ("numbered
  inline citations plus a trailing `# Citations` section", inherited from the B3Wiki
  exercise). Two consequences if accepted: (a) ROADMAP/REQUIREMENTS wording needs a
  one-line amendment; (b) B3Wiki fixtures are *structural* parity (mapping rules),
  not byte parity, for this one rule.
  **Alternative (roadmap-as-written):** numbered `[1]` + trailing `# Citations`,
  B3Wiki/`okflint` parity, still tolerated by v0.2 consumers as legacy. Whichever
  wins, the writer and `migrate-okf` MUST use the same notation — a vault must not
  mix both.
- **D-13:** One `sources[]` entry per raw record: `id` = raw path stem (stable,
  unique), `resource` = `/raw/<file>.md` (bundle-relative), `title` = raw page
  title or `source_url`, `last_modified` = the raw record's `ingested` timestamp.
  **No `author`, no `usage_count`, no `usage_window`** — credibility signals are
  claims and we have no evidence for them (honesty rule).
- **D-14:** Ordering is deterministic: sources listed in first-appearance order;
  a page with frontmatter provenance but no inline markers still lists every
  source in `sources[]` and emits no footnotes.

### raw/ layer conformance (OKF-05)

- **D-15:** `raw/*.md` records become OKF concepts with **`type: Source`**
  (B3Wiki parity, and the only reading that satisfies v0.2 §11 strictly): the
  frontmatter written by `vault::raw::write_raw` gains `type: Source`, `title`,
  `timestamp`, `generated: { by: process:saussunet/<version>, at: <ingested> }`
  and keeps `source_url`/`ingested`/`sha256` as extension keys. The **body stays
  byte-immutable** — only the frontmatter block is ours.
  (Under v0.3 this would be optional: §3.2 rule 2 makes a `.md` without `type` a
  non-concept that does not affect conformance. Choosing 0.2 means we do this.)
- **D-16:** Binary raw records (uploaded PDFs) are OKF **assets**, not concepts —
  no frontmatter, byte-exact rule unchanged.

### index.md and log.md (OKF-04)

- **D-17:** Root `index.md` gains a frontmatter block containing **only**
  `okf_version: "0.2"` (quoted) — the one place frontmatter is permitted in an
  index. Body keeps the sectioned, alphabetical, counter-bearing llm-wiki shape.
- **D-18:** Index entries become `- [Title](/path.md) — description` (spec §8
  shape). `vault::index::upsert_entry` and the validator's whitelist parser
  (`validate.rs` parses `- [[stem]] — title` today) change **together** — one
  format, one migration point, pinned by tests on both sides.
- **D-19:** `log.md` entries group under `## YYYY-MM-DD` headings, **newest
  first**, as bullets `* **<action>**: <subject>` preserving the llm-wiki action
  vocabulary (ingest, update, create, lint, create, refuse…). New entries insert
  at the top, creating today's group when absent. `entry_count` / `should_rotate`
  / `fresh_header` count bullets, not `## [` headings; the 500-entry rotation
  behaviour is otherwise unchanged. `log.md` carries no frontmatter.

### Write-path conformance gate (OKF-05)

- **D-20:** Extend the existing PIPE-06 gate (`vault::validate::validate_page`)
  with the OKF checks: parseable frontmatter; non-empty `type` inside the allowed
  vocabulary (D-02/D-03); every timestamp ISO 8601 with explicit offset; each
  `sources[]` entry carries a non-empty `resource`; `generated.by` matches the §7
  actor convention. All violations still collected into ONE `CoreError::Validation`
  (existing pattern). Broken cross-links are counted, never rejected. The raw
  existence check and the Pitfall-4 self-citation rejection are unchanged.
- **D-21:** The §11 rule set lives in **one module** (e.g. `vault::okf`) consumed
  by three call sites: the write-path gate, `migrate-okf --dry-run`/`--verify`,
  and (later) Phase 5 lint. It is the Rust port of B3Wiki `scripts/okflint.py`
  (errors E1–E4, warnings W1–W3) — one implementation of conformance, not three.
- **D-22:** Scope guard: bundle-wide reporting (orphans, vault-wide broken-link
  list, index completeness) stays in Phase 5 (LINT-01). Here the checker runs
  per-page at write time and per-vault only inside `migrate-okf`.

### `saussunet migrate-okf` (OKF-06)

- **D-23:** `saussunet migrate-okf --vault <name>` **defaults to dry-run**: a
  report of files to change, per-rule counts, skipped protected pages, and the
  post-conformance verdict. Nothing is written without `--apply`. `--json` for
  machine-readable output.
- **D-24:** Refuse an already-converted vault: root `index.md` carries
  `okf_version`, **or** ≥ 80% of non-reserved pages already carry `generated:`
  (same threshold shape MoriNet uses in `18-CONTEXT.md` D-03). Refusal is
  terminal — no `--force`. `--verify` re-runs the conformance check on an
  already-converted vault without writing anything.
- **D-25:** Undo path: if the vault root is a git repo with a **dirty** worktree,
  refuse (git history is the backup and it must be clean to be useful). A non-git
  vault refuses unless `--backup <dir>` is supplied, which writes an archive of
  the tree first.
- **D-26:** Pages marked `protected: true` are **skipped and reported** (human-
  owned, Phase 1 D-07). Every page the migration rewrites gets its `gen_hash` map
  **re-seeded** afterwards, so the conversion never reads as a human edit on the
  next pipeline merge (this is the `ghash.rs` three-way-merge landmine).
- **D-27:** Conversion runs under the vault single-writer lock through
  `vault::atomic::write_atomic` — never direct fs writes (Pitfall 6). It ends with
  a `reindex` so SQLite matches the converted tree, and appends a `log.md` entry
  describing the migration.
- **D-28:** The converter lives in `saussunet-core` (embeddable by MoriNet, which
  keeps core axum-free per the CI guard); the binary crate only adds the clap
  subcommand.

### Testing

- **D-29:** Port the B3Wiki `tests/test_to_okf.py` cases to Rust fixtures (small
  synthetic vault trees in `tempdir`) and add one `#[ignore]`d parity test that
  converts a local B3Wiki checkout and asserts the Rust checker reports 0 errors.
  TDD RED-first, MockProvider only, zero real LLM in CI, `scripts/check.sh` green.

### Claude's Discretion

- Exact CLI flag spellings beyond `--vault` / `--apply` / `--dry-run` / `--json` /

- Whether `index.md` sections are regrouped by the new `type` values or keep the
  four llm-wiki sections (either is conformant; pick the smaller diff).
- How an index entry renders when a page has no description.
- Whether `SCHEMA.md`/`README.md` get `type: Schema`/`Readme` (B3Wiki did) or stay
  non-concepts — v0.3 explicitly allows either; pick one and make the checker agree.
- Jitter/batching of the migration pass; report formatting details.

<code_context>
## Existing Code Insights

### Reusable Assets
- `vault::writer::write_page` — single serialized mutation funnel (path guard,
  frontmatter validation, gen_hash three-way merge, atomic write, index/log
  projection). Every OKF change lands inside this funnel; nothing bypasses it.
- `vault::validate::link_whitelist` — already resolves index stems ∪ registry
  `page_path` stems: it is 90% of the wikilink→path resolver D-09 needs.
- `vault::frontmatter::{split,parse,serialize}` with unknown-key preservation —
  the "parse lenient, serialize strict" property OKF-MAPPING lesson #3 requires.
- `vault::atomic::write_atomic` + `vault.write_lock` — the migration's write path.
- `reindex` — rebuilds `page_registry` from disk; the post-migration projection fix.
- `store::entities::resolve_entity` / `page_type` column — carries the D-03 subtype.
- B3Wiki `to_okf.py` + `okflint.py` + `test_to_okf.py` — a working, tested port
  target in Python; the Rust port is a translation, not an invention.
- MoriNet `src/okf.rs::scan_conformance`/`trust_tier` — the consumer's view of the
  same rules; use it as a cross-check that our output reads the way MoriNet expects.

### Established Patterns
- Deterministic validator rejects BEFORE any disk write, all violations in one
  `CoreError::Validation` (Phase 3 PIPE-06) — OKF checks follow the same shape.
- Tolerant parse, strict serialize; unknown fields never fatal (Phase 2 D-05).
- `saussunet-core` stays axum-free (CI guard); CLI surface lives in the binary crate.
- Non-destructive at every branch: protected pages refuse, gen_hash mismatch skips
  and records a proposal, contradictions flag — migration must inherit this bias.
- TDD RED-first with MockProvider/stub fixtures; `scripts/check.sh` is the gate.

### Integration Points
- `write_page` / `write_generated_page`: link rewrite → citation rewrite →
  frontmatter serialization → OKF validation → gen_hash re-seed.
- `pipeline::prompts` pass-2 instruction: replace the "≥2 outbound `[[wikilinks]]`"
  wording with the same instruction in wikilink notation (unchanged LLM contract)
  and add the `description` + entity-subtype fields.
- `watch`/`ingest_raw` path: raw writes must emit the new `type: Source` frontmatter.
- New `vault::okf` module ← consumed by `validate.rs`, `migrate`, (Phase 5) lint.
- New clap subcommand `migrate-okf` in `crates/saussunet/src/main.rs`.
- `SCHEMA.md` seed template (OKF-07) — the vault's own contract text.

### Landmines (found by reading the code)
- `raw/*.md` today carry `source_url/ingested/sha256` and **no `type`** → they fail
  §11 as written (`raw.rs:41`). D-15 is the fix; the migration must touch them.
- `validate.rs` whitelist parses `- [[stem]] — title` from `index.md`; changing the
  index entry format without changing the parser silently empties the whitelist and
  every page starts failing the link check (or worse, passes with no whitelist).
- `ghash.rs` treats a body change it did not make as a human edit → an un-re-seeded
  migration makes every page look human-edited and the next pipeline merge skips
  writes + files proposals (D-26).
- `log.rs::entry_count` counts `## [` lines; date-grouped headings break that count
  and therefore rotation (D-19).
- `frontmatter::serialize` must emit nested `sources:` lists-of-maps and
  `generated: {by, at}` — today's model is flat strings + `serde_yml::Mapping` passthrough.

<specifics>
## Specific Ideas

- "The vault is the artifact" — the point of this phase is that a stranger cloning
  the vault sees a spec-conformant OKF bundle with no SaussuNet-specific dialect to
  learn. Where a choice exists between llm-wiki habit and OKF idiom, OKF idiom wins.
- Honesty over completeness: an empty `sources[]` or a missing credibility signal is
  better than an invented one. The honesty rule is the phase's taste level, not just
  a rule (OKF-MAPPING "Honesty rule"; PROJECT.md Key Decisions).
- B3Wiki is the worked example: `git -C /home/c/Projects/Dev/B3Wiki show okf` (or
  its `main` tree) shows a real 161-file bundle that passes `okflint.py` with 0
  errors — the researcher should read a couple of converted pages, not just the docs.
- MoriNet is the first consumer: whatever this phase writes will be scanned by
  `MoriNet::okf::scan_conformance` and served over WebDAV/REST/MCP. A vault that
  converts cleanly but reads as "not an OKF bundle" in MoriNet is a failed phase.
- The migration is a one-time, auditable, narrated event (report + `log.md` entry),
  not a silent rewrite — the user's vaults are assets, not build output.

</specifics>

<deferred>
## Deferred Ideas

- **OKF v0.3 adoption** — declare `okf_version: "0.3"`, add root-index bundle
  metadata (`title`, `description`, `license`), `superseded_by`, and drop the
  `type: Source` requirement on `raw/` (v0.3 §3.2 makes non-`type` .md files
  non-concepts). Small follow-up phase once MoriNet and B3Wiki move too.
- **Trust fields with real evidence** — the Phase 5 review UI approving a page is
  exactly a `verified: { by: human:<id>, at }` event; that is where `verified`
  (and eventually `status`/`stale_after`) legitimately enter the vault.
- **Credibility signals** — `sources[].usage_count` / `author` fed by real read
  statistics (MoriNet has per-vault stats); never invented.
- **Per-directory `index.md` files** — only the root index exists today; §8 allows
  one per directory. Worth it only if vaults grow past a few hundred pages.
- **Dropping the `created`/`updated` llm-wiki extension keys** — keep for one
  release for Obsidian compatibility, then remove once nothing reads them.
- **Bundle-wide lint reporting** (orphans, vault-wide broken-link list, index
  completeness) — Phase 5 LINT-01, now worded in markdown-link terms.
- **B3Wiki housekeeping** (their repo, not ours): `SCHEMA.md`/`AGENTS.md` prose
  still describes llm-wiki conventions; `scripts/lint.py` is stale post-conversion.
