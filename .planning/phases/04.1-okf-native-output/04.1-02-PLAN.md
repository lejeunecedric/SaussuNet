# Plan 04.1-02: index + log OKF rework

## Objective
As a vault consumer, I want `index.md` to declare `okf_version: "0.2"` with spec-§8 markdown entries and `log.md` to be a date-grouped, newest-first activity log (OKF §8/§9) — without the link whitelist silently breaking, which is the phase's #1 landmine (Pitfall 1: `validate.rs:35` parses `- [[stem]] — title` today; changing the writer without the parser empties the whitelist and every page fails the link check).

**User story slice:** after an ingest, the index shows `- [Title](/concepts/foo.md) — description` under `okf_version: "0.2"`, the log shows today's `## YYYY-MM-DD` group with `* **ingest**: …` at the top, and page validation still resolves links — all proven by the paired test on both sides.

## Context
- The four coupled `- [[` touchpoints, verbatim in PATTERNS §5: `index.rs:63-64` (entry + dedup prefix), `index.rs:68,80` (section rebuild filters), `index.rs:88` (counter), `validate.rs:34-43` (whitelist parser). ALL flip in this plan's Task 1, same commit.
- Discretion decision recorded: the `Total pages: N` counter counts new-format entry lines (`- [Title](/path.md)` prefix) in the same commit as the format change (RESEARCH open Q4).
- Discretion decision recorded: index keeps the four llm-wiki section headings (Concepts/Entities/Comparisons/Queries) — smaller diff, still conformant (CONTEXT discretion).
- Whitelist semantics after the flip: stem recovered from the path's file_stem (`/concepts/foo.md` → `foo`) because the whitelist is stem-keyed (validate.rs:29-56). Plan 04.1-03 will additionally want stem→path; make the parser return `HashMap<String /*stem*/, String /*/path.md*/>` internally or keep stems + a parallel path map — the resolver in 04.1-03 consumes it.
- Log call sites pass `## [date] action | subject` headers today — SEVEN external call sites: `writer.rs:146-157, 175-186, 205-216, 282-287`, `watch/mod.rs:267` and `watch/mod.rs:490` (poll deltas as multi-line `lines` vectors), and `pipeline/mod.rs:500` (drift entry); plus one inline test call in `log.rs:159`. `append_entry` (`log.rs:61`, current signature `(vault, header: &str, lines: &[String])`, rotation branch :82-99) flips to `(vault, action: &str, subject: &str, details: &[String])` inserting under today's group at top; `details` render as indented sub-bullets (`  - <detail>`) under the main `* **{action}**: {subject}` bullet — this keeps a slot for the writer detail lines (`- proposal recorded (pending_proposals #N)` etc., writer.rs:152-155) and the watch delta vectors.
- Pitfall 3: `entry_count` (`log.rs:33-35`) counts `## [` — must count `* ` bullets under date groups or rotation never fires; `fresh_header` (`log.rs:44-54`) splits at first `## ` date heading; `ROTATION_THRESHOLD = 500` (`log.rs:12`) unchanged.
- Pitfall 8: `sanitize_for_nav` (`writer.rs:34-36`) collapses `## [`; extend to neutralize `## ` followed by a digit (forged date heading in a title).

<threat_model>
- **Log injection (HIGH, block):** a page title/subject containing `## 2026-01-01` or `## [` must not forge a log date group or entry — extend `sanitize_for_nav` and pin with a test (Pitfall 8).
- **Whitelist-emptying regression (HIGH, block):** the paired T6 test asserts the whitelist is non-empty AND stem-correct after the format flip; a commit where writer and parser disagree fails T6, preventing the silent-empty failure mode (Pitfall 1).
- **Path traversal via index entries (MED):** the whitelist parser only accepts entry paths that are bundle-relative `/dir/file.md` with no `..` component; anything else is skipped (never added to the whitelist).
- **Atomic writes only:** index/log continue to be written through the existing funnel (`write_atomic` under `write_lock`); no new write sites; write-funnel grep stays green.
</threat_model>
