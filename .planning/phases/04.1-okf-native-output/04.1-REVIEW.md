# Phase 04.1 Code Review — OKF-Native Output

Reviewed the source diff `0ebf761..HEAD` (34 files, ~5.4k insertions): `vault/okf.rs` (new §11 checker + rebuild), `vault/log.rs` / `vault/index.rs` (OKF §8/§9 rework), `vault/frontmatter.rs` (nested OKF serialization), `vault/writer.rs` (generated-page funnel), `vault/validate.rs`, `vault/raw.rs`, `vault/schema.rs`, `pipeline/{mod,pages,prompts,schemas}.rs`, `watch/mod.rs`, `migrate.rs` (new), `saussunet/src/main.rs` (migrate-okf CLI). Declared deviations in the five SUMMARY files were accepted as documented; findings below are issues those summaries do not cover.

## HIGH

### H1 — `log.md` header block is duplicated on every append into an existing date group
**File:** `crates/saussunet-core/src/vault/log.rs:126,137`

`append_entry` builds `out = lines[..header_end]` (line 126), then in the `Some(p)` branch (today's `## YYYY-MM-DD` group already exists) extends with `lines[..=p]` (line 137) — which re-includes `lines[..header_end]`, the header block that is already in `out`. Every append into today's group copies the whole pre-heading region once more.

**Verified empirically** (probe crate against the real code): seed + 2 appends → `# Wiki Log` appears **4 times** in `log.md`. This is the hot path: every `write_page` appends a log entry, and the seeded log already contains today's group, so every pipeline write corrupts `log.md` cumulatively.

Why the tests missed it: `log_date_groups` (tests/okf_index_log.rs:121) only uses `contains()` and relative-order assertions, and `check_log` only scans `## ` headings — a duplicated `>`-quoted header is invisible to both.

**Fix:** in the `Some(p)` branch use `out.extend(lines[header_end..=p].iter().cloned())` instead of `lines[..=p]`, and add a regression test asserting `log_md.matches("# Wiki Log").count() == 1` after appends into an existing group.

### H2 — `migrate-okf --apply` produces a vault the pipeline can never write to again (missing `## Entity Subtypes` in migrated SCHEMA.md)
**Files:** `crates/saussunet-core/src/migrate.rs:690-716` (`convert_meta`), `crates/saussunet-core/src/vault/schema.rs:56-90` (`parse_entity_subtypes`), `crates/saussunet-core/src/vault/writer.rs:138`

`write_page` (the sole mutation funnel, human and generated paths) now hard-calls `schema::parse_entity_subtypes(vault)?`, which fails loud when SCHEMA.md has no `## Entity Subtypes` section (schema.rs:85). But `convert_meta` only prepends `type: Schema` + `title` frontmatter to SCHEMA.md (migrate.rs:711) and leaves the legacy body untouched — legacy SCHEMA.md bodies have no Entity Subtypes section (the T11 fixture at tests/migrate_okf.rs:88-90 is exactly such a legacy SCHEMA). Result: `migrate-okf --apply` reports success, then **every subsequent `write_page` / `write_generated_page` on the migrated vault fails** with `no entity subtypes found under '## Entity Subtypes'`. The migrate tests never call `write_page` after `apply`, so the gap is untested.

**Fix:** have `convert_meta` (or a dedicated rule in `convert_file` for `SCHEMA.md`) append the `## Entity Subtypes` section (default vocabulary `Person, Organization, Tool, Place, Event, Work`) when absent; add a test that runs `write_generated_page` against a migrated mini-bundle.

## MEDIUM

### M1 — `check_bundle` hardcodes `DEFAULT_TYPE_VOCAB`, so `--verify` false-flags legitimate entity-subtype pages
**File:** `crates/saussunet-core/src/vault/okf.rs:883`

The write path legitimately emits `type: Person` / `Organization` / … (D-03 fold, kept by `rebuild_frontmatter` because SCHEMA subtypes extend its `type_vocab`), but `check_bundle` calls `check_page(fm_yaml, body, &DEFAULT_TYPE_VOCAB)` with the fixed 7-value set. `migrate-okf --verify` (and the Phase-5 lint consuming the same entry point) therefore reports spurious `E2: type "Person" not in the accepted vocabulary` errors on a fully conformant SaussuNet vault, and `verify` exits 1. D-21's "one implementation of conformance" requires one *vocabulary* too.

**Fix:** give `check_bundle` a `type_vocab` parameter (or have it read the vault's SCHEMA subtypes like `rebuild_frontmatter` does) and pass it from `migrate::verify`.

### M2 — LLM-controlled `description` reaches `index.md` unsanitized (nav-injection vector)
**Files:** `crates/saussunet-core/src/vault/writer.rs:308`, `crates/saussunet-core/src/vault/index.rs` (`upsert_entry`)

`write_page` passes `fm.description.as_deref()` straight into `upsert_entry`, which interpolates it verbatim into the index line `- [Title](/path.md) — {desc}`. The title goes through `sanitize_for_nav` (line 307); the description does not. `description` is first-class pass-2 LLM output (D-07, `PageContent.description`, only `.trim()`ed in pipeline/pages.rs), so a description carrying `\n- [Fake](/evil.md) — x` forges index entries — which then feed `validate::index_entry_map` / `okf::build_slug_map`, i.e. the link whitelist. This is the same Pitfall-8 class `sanitize_for_nav` exists for (and which the log path correctly sanitizes).

**Fix:** `sanitize_for_nav` the description before passing it to `upsert_entry` (and consider it in `rebuild_frontmatter` when accepting the LLM description).

## LOW

### L1 — `already_converted` denominator includes reserved/meta files that never carry `generated:`
**File:** `crates/saussunet-core/src/migrate.rs:897,912`

The 80 % check skips only root `index.md`/`log.md`; nested `index.md`/`log.md` (reserved by the phase's own deviation #2), `SCHEMA.md` and `README.md` (which `convert_meta` writes with only `type`+`title`) count in `total` but can never count in `generated`. On small vaults with several section catalogs the post-conversion ratio can fall below 80 %, so the fallback refusal branch may not fire (the root-index `okf_version` check usually catches it first). Fix: exclude reserved basenames and meta files from the denominator, mirroring `build_tree`'s reserved rule.

### L2 — `count_broken_links` walks `.git` and follows symlinked directories
**File:** `crates/saussunet-core/src/vault/okf.rs:414-430` (`if path.is_dir()` follows symlinks; no `SKIP_DIRS` filter)

Unlike `migrate::walk` and `check_bundle` (both symlink-safe, SKIP_DIRS-honoring), this scanner descends into `.git`/`node_modules` and follows symlinked dirs — contradicting the module's own "never followed" threat model and adding noise/perf cost on every `finish()`/`verify`. Fix: reuse the `check_bundle` walk shape (lstat + `SKIP_DIRS`).

### L3 — `reformat_log` silently drops non-date `## ` headings that precede the first date group
**File:** `crates/saussunet-core/src/migrate.rs:372`

When a `## Notes`-style heading appears before any date group, `cur` is `None` and the `else if let Some(d) = &cur` branch discards the heading and its content — contradicting the function's own "migrate never drops content" comment (which only holds once a date group has been seen). Fix: buffer pre-first-group non-date sections into the head, or emit them under a synthesized group.

### L4 — `rebuild_frontmatter` can still emit an empty `description` (D-07 edge)
**File:** `crates/saussunet-core/src/vault/okf.rs:614`

If the body has no prose line (all headings/quotes/tables), `first_sentence` returns `""` and the page ships `description: ""` — D-07 says "a generated page never ships an empty description". Fix: fall back to the title (or the stem) when `first_sentence` is empty.
