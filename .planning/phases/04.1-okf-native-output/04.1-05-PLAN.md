# Plan 04.1-05: `migrate-okf` — in-place conversion with refusals and B3Wiki parity

## Objective
As an operator with an existing llm-wiki vault, I want `saussunet migrate-okf --vault main` to show me exactly what it would change (dry-run default), refuse anything unsafe (already-converted vault, dirty git tree, no backup), and on `--apply` convert the vault in place to a conformant OKF bundle — auditable (report + log.md entry), reversible (git or backup), and invisible to the next pipeline merge (gen_hash re-seeded).

**User story slice:** synthetic llm-wiki vault in a TempDir → dry-run writes nothing and reports per-rule counts → `--apply` converts → `check_bundle` reports 0 errors → reindex matches the tree → refusal cases refuse terminally → (ignored) B3Wiki full-tree parity.

<threat_model>
- **Path traversal on migrate walk (HIGH, block):** canonicalize the vault root once; every file path is derived from the walk and re-checked to stay under the canonical root (reject symlink escapes via canonicalize-per-file or symlink_metadata skip); nothing outside the root is ever read for write or written. Test: a vault containing a symlink pointing outside the root is skipped (reported), not followed.
- **Secret leakage in reports (HIGH, block):** MigrateReport carries relative paths, rule ids, counts, and verdict ONLY — never page bodies, frontmatter values, or config secrets; --json serialization test asserts no absolute paths and no body text appear in the JSON.
- **Refusal bypass (HIGH, block):** all refusal checks (converted, git-dirty, non-git-without-backup, protected-skip) run BEFORE any write and are re-asserted inside the apply path; there is no --force flag in the clap surface at all (absence is the guarantee); T12 asserts zero filesystem mtime changes on every refusal branch.
- **Atomic writes only (HIGH, block):** every mutation goes through `atomic::write_atomic` under `vault.write_lock` (D-27); `scripts/check.sh` write-funnel grep must stay green (no fs::write/File::create in migrate.rs); backup archive failure aborts before the first mutation.
- **Data loss (HIGH, block):** git-dirty refusal + backup-first posture (D-25); protected pages untouched (T12 asserts byte-identical); gen_hash re-seed correctness asserted in T11 (stored map == compute_map over final bytes) so the conversion cannot poison future merges (Pitfall 2).
</threat_model>
