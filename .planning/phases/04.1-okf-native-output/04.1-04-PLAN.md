# Plan 04.1-04: SCHEMA.md OKF contract + entity subtypes + first-class description

## Objective
As a consuming agent, I want the vault's own SCHEMA.md to state the OKF conventions and the entity subtype vocabulary, and I want entity pages to carry a descriptive subtype (`Person`, `Organization`, `Tool`, …) chosen by pass-2 but constrained and folded deterministically — so the vault is self-describing and `type` values are meaningful, never model hallucinations.

**User story slice:** MockProvider ingest of a person-heavy source → the entity page lands with `type: Person`; a model that answers `Alien` (or omits it) still lands `type: Entity` and the pass succeeds; SCHEMA.md on disk documents all of it.

## Context
- `schema.rs::seed(domain)` (:53-157) is the llm-wiki template; PATTERNS §9 lists the three rewrite zones: frontmatter template (:77-91), raw/ template (:97-111 — gains `type: Source` per D-15), conventions list (:60-75). Seed tests at :163-185 update in the same commit.
- **Hard coupling (PATTERNS §9):** `parse_tag_taxonomy` (:12-49) parses `- Category: tag1, tag2` bullets under `## Tag Taxonomy` and fails loudly when empty (:40-47) — keep that section shape verbatim. `parse_entity_subtypes` is a new fn beside it with the same bullet-scanner shape, reading `## Entity Subtypes` (bullets `- Person`, `- Organization`, … or one comma list — pick the comma-list form mirroring the taxonomy scanner, simplest reuse).
- `PageContent` (pipeline/schemas.rs:77-94): `{title, page_type, tags, summary, sections, contested, contradictions}` gains `description: String`; `json_schema_hint()` (:96-106) is embedded in the prompt — update both together (PATTERNS §10). `summary` keeps its `## Summary` body-section role (pages.rs:305-309); `description` is the one-line frontmatter summary (OKF-MAPPING lesson #4).
- Tolerant fold precedent: pages.rs:283-287 — "trust the model only within the taxonomy of page types". The subtype fold mirrors it: `if subtypes.contains(&page_type) { subtype } else { "Entity" }`, never an error (D-03, Phase 2 D-05).
- The subtype reaches the write path via `entity_registry.page_type` (store::entities::resolve_entity) — the 04.1-01 rebuild already reads registry page_type for entities/ pages; this plan makes the stored value the SCHEMA-vocabulary subtype.
- prompts.rs pass-2 TASK block (:92-101): keep the `≥2 outbound [[wikilinks]]` instruction verbatim (unchanged LLM contract, RESEARCH Pattern 2); add: one-line `description` field + `page_type` = entity subtype from the declared list (for entity pages). Its test asserting `p.contains("[[wikilinks]]")` (prompts.rs:171) stays green.
- validate.rs: wire `schema::parse_entity_subtypes` output into the `check_page` vocabulary parameter (hook left by 04.1-01) so gate acceptance == declared contract.

<threat_model>
- **Prompt-injection / hallucinated type (HIGH, block):** the model's `page_type` string is NEVER emitted raw — deterministic fold to the SCHEMA-declared vocabulary, else `Entity`; test `entity_subtype` pins both branches. A subtype string containing YAML/markdown metacharacters cannot reach disk (fold rejects anything not exactly in vocabulary).
- **SCHEMA parse DoS on writes (MED, block):** parse failure behavior unchanged from parse_tag_taxonomy precedent (fail loudly at write with a named error, not silently); malformed subtype section must not panic — scanner is line-based, no YAML.
- **Honesty rule:** the SCHEMA.md template documents that `verified`/`status`/`stale_after` are never emitted without evidence (mirrors PROJECT.md Key Decisions); the template itself must not instruct writers to add them.
- **No new write sites:** SCHEMA.md continues to be seeded through the existing init path; atomic-write funnel untouched.
</threat_model>
