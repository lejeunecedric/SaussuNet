## Decisions

- `sources` as `Vec<serde_yml::Value>` (not a new enum or two fields): both legacy flat strings and OKF maps round-trip through `parse`/`serialize` with zero data loss, keeping `write_page`'s re-serialize byte-consistent.
- OKF-mode serialize builds ONE `serde_yml::Value::Mapping` and stringifies whole (RESEARCH anti-pattern: no hand-rolled nested pushes); flat path preserved verbatim so human/CLI writes stay byte-stable and existing gen_hash semantics are untouched.
- `rebuild_frontmatter` reads the existing page's `created` (mirroring write_page step 5) so `generated.at` matches the value `write_page` will persist — D-08 no-drift holds on updates too, not just first writes.
- `check_page` parses `fm_yaml` as a raw `serde_yml::Value` (not `PageFrontmatter`) so E1/E2 can distinguish unparseable vs non-mapping vs non-string `type`, matching okflint semantics exactly.
- Wave-1 entity typing: registry `page_type` accepted only if already capitalized-vocab (it stores lowercase today) → entities/ folds to `Entity`; SCHEMA subtypes land in 04.1-04 as planned.

## Lessons

- **serde_yml 0.0.13 (noyalib) API differs from serde_yaml 0.9**: `Mapping` keys are `String` (`insert(impl Into<String>, Value)`, `get(&str)`), and `to_string` does NOT emit a trailing newline — a closing `---` glued to the last frontmatter line silently breaks the split contract (symptom: parse returns default struct). Always `if !yaml.ends_with('\n') { push }`.
- `"key".into()` into `impl Into<String>` params is ambiguous (E0283) — use `.to_string()` at call sites.
- noyalib quotes date-like and colon-bearing strings when emitting; pin tests against the parsed value, not the raw scalar style.
- Changing a widely-read struct field type (`sources`) ripples into integration-test assertions — grep `\.sources` across `tests/` before the change, not after.
