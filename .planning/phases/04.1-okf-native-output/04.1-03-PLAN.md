# Plan 04.1-03: wikilink resolver + footnote citations

## Objective
As a vault consumer, I want generated pages on disk to contain zero `[[wikilinks]]` and zero raw `^[raw/...]` markers — instead bundle-relative markdown links and footnotes keyed to `sources[].id` — while the LLM prompt contract stays byte-identical (the rewrite is deterministic, in the writer). This completes ROADMAP criteria 1 (zero wikilinks) and 2 (footnote provenance).

**User story slice:** MockProvider ingest → open the page: prose links are `[Title](/concepts/foo.md)`, claims end in `[^raw-2026-10-30-foo]`, definitions sit at the bottom, `sources[]` ids match the footnote keys exactly.

## Context
- Insertion point already opened by plan 04.1-01: the rebuild step inside `write_generated_page` (writer.rs, between `validate_generated_page` and `write_page`). This plan inserts the two rewrite steps BEFORE the frontmatter rebuild (citation rewrite must run before `sources_entries` finalization so footnote ids and `sources[].id` are the same values — build sources first or share the walk; RESEARCH Pattern 2 order: links → citations → frontmatter).
- Slug→path resolver source: `validate::link_whitelist` (validate.rs:29-56) already unions index stems ∪ entity canonical names ∪ registry `page_path` stems; after plan 04.1-02 the index parser also knows paths. `build_slug_map` returns `HashMap<String /*stem*/, (String /*title*/, String /*/path.md*/)>` from: page_registry rows (stem → rel_path, title from frontmatter), entity `page_path`, and the page's own stem (self-links excluded from the floor as today).
- Port targets (verbatim anchors in RESEARCH port_inventory): `rewrite_wikilinks` ← to_okf.py:159-182 (aliased `[[slug|alias]]`, bare→title, path-style `[[a/b]]`, broken-tolerated `:178`); `rewrite_citations` ← to_okf.py:185-194 first-appearance dedup walk BUT footnote output per D-12 — `citations_section` (:197-201) is NOT ported.
- The first-seen walk to reuse: `validate::extract_provenance` (validate.rs:87-101, verbatim in PATTERNS §4).
- Floor flip: `writer.rs:110-115` currently rejects `< 2` wikilinks inside `write_page` (human path). Keep `write_page`'s human-path check as-is; the generated path re-counts post-rewrite with `count_outbound_markdown_links` inside the wrapper (D-10: floor survives on markdown links). `count_outbound_markdown_links` scans `](/` per okflint `MD_LINK` (`okflint.py:39`), plain-scan precedent `frontmatter.rs:209-228`; dedupe by target like the wikilink counter.
- B3Wiki `TestWikilinks` ×5 (test_to_okf.py:13-51) port as unit cases of `rewrite_wikilinks`; `TestCitations` ×2 (:54-66) adapt to footnote form (D-29).

<threat_model>
- **Path traversal via resolved links (HIGH, block):** resolved paths come only from page_registry/entity-registry values already validated against `PAGE_DIRS` (vault/mod.rs:95-126 path guard) — the resolver never concatenates LLM text into a path; unresolvable slugs render `/slug.md` literally and are counted broken, never written as filesystem targets. A slug containing `../` must not produce a `..` path: sanitize slug input (reject slugs containing `/` or `..` from the resolvable map; they fall through to the broken-link form with the `..` stripped).
- **Notation mixing (MED, block):** writer and migrate MUST share `okf::rewrite_citations` (D-12 warning); test asserts no `# Citations` heading and no bare `^[` on disk after any pipeline write.
- **Injection via alias text (MED):** `[[slug]|alias]]` alias text is markdown-in-body (already LLM-authored); the rewrite must not let alias text escape the link syntax (strip `]` from aliases).
- **Atomic writes only:** no new write sites; everything still lands through `write_page` → `write_atomic` (write-funnel grep green).
</threat_model>
